How procedural track generation works

Every RL episode gets a brand-new closed-loop racetrack, built deterministically from one integer seed. This course walks the whole pipeline: from a handful of random points, to a smooth spline, to a physically valid corridor with collidable walls, to the 23-number view the agent actually learns from. Code and math side by side, one stage at a time.

Module 0

The big picture & the one invariant

env.py · walls.py

Before any code: the whole system is a pipeline from one integer to one drivable world. Trace a single seed through it and everything else falls into place.

seed (int)→ control points→ periodic spline→ uniform arc-length samples→ + width→ validate / repair→ Track→ walls + spawn→ step loop

The output of generation is one immutable object, Track. It is nothing but a bag of NumPy arrays, all length M = 2048, sampled evenly along the loop. Every later stage — walls, spawn, projection, reward, observation — reads only this object.

@dataclass(frozen=True)
class Track:
    C:     np.ndarray  # (M,2) centerline positions (x,y)
    T:     np.ndarray  # (M,2) unit tangents
    Nrm:   np.ndarray  # (M,2) unit LEFT normals (T rotated +90°)
    kappa: np.ndarray  # (M,)  signed curvature, + = turning left
    w:     np.ndarray  # (M,)  half-width
    s:     np.ndarray  # (M,)  arc length: s[i] = i * L / M
    L:     float       # total lap length
    seed:  int
INV-1 — the architecture invariant The compiled MuJoCo model has identical topology for every episode and every seed: floor + car + a fixed pool of 512 wall capsules. A new track never recompiles anything — reset only rewrites array fields (geom_pos, geom_quat, geom_size) in place. That is the single rule that makes the later GPU (MJX) port a mechanical array-swap instead of a rewrite. Hold onto it; it explains half the design choices below.

Determinism is the other backbone. A single np.random.default_rng(seed) drives all randomness, consumed in a fixed order. Same seed in → bit-identical track, walls, and rollout out. Repair logic uses no randomness at all, precisely to keep this promise.

Module 1

The centerline shape

generator.py · make_centerline

Goal: a closed loop that is smooth, roughly round, but not boringly circular — it should sometimes produce S-bends. The recipe: scatter points around a ring, wiggle them, smooth them, then draw a curve through them.

Step 1 — points on a ring

Pick n control points (10–17). Each gets a random angle θ and random radius r. In polar-to-Cartesian form:

polar → xy pi = ( ri cos θi,  ri sin θi ),   θi ∈ [0, 2π) sorted,  ri ∈ [6, 9] m

Sorting the angles makes the points wind once around the circle in order — that is what guarantees a simple closed loop rather than a tangled scribble. respace_min_gap then pushes any two angles that landed too close (< 0.15 rad) apart, so no two control points nearly coincide and force a hairpin.

Step 2 — smooth the radii, then jitter, then smooth the points

def make_centerline(rng, cfg):
    n = int(rng.integers(cfg.n_ctrl_min, cfg.n_ctrl_max + 1))
    theta = np.sort(rng.uniform(0, 2*np.pi, n))
    theta = respace_min_gap(theta, cfg.min_angular_gap)     # no near-duplicates
    r = rng.uniform(cfg.r_min, cfg.r_max, n)
    for _ in range(cfg.radius_smooth_rounds):        # circular smoothing on radii
        r = 0.5*r + 0.25*(np.roll(r, 1) + np.roll(r, -1))
    pts = np.stack([r*np.cos(theta), r*np.sin(theta)], axis=1)
    pts += rng.normal(0.0, cfg.jitter_std, pts.shape)  # the wiggle
    for _ in range(cfg.laplacian_rounds):
        pts = 0.5*pts + 0.25*(np.roll(pts, 1, 0) + np.roll(pts, -1, 0))
    return pts

The smoothing is a Laplacian (moving-average) filter on a ring. Each point is pulled toward the average of its two neighbours:

one smoothing round pi ← ½ pi + ¼ (pi−1 + pi+1)

np.roll is what makes it circular — index i−1 of the first point wraps to the last, so the loop stays seamless. This kills sharp zig-zags (high curvature) between adjacent points.

Why smooth radii separately? Smoothing the points shrinks the whole loop toward its centroid (a moving average pulls inward). Smoothing the radii alone tames sudden in/out jumps — the real curvature troublemaker — without shrinking the track. That is why both steps exist.

Tuning reality vs. the plan The plan suggested r 3–6 m, jitter 0.8. Measured, those gave median max-curvature ≈ 1.06 m⁻¹ and length ≈ 22 m — zero valid phase-0 tracks, and repair couldn't close the gap. The shipped values (r 6–9, jitter 6.0, 2 rounds) yield ~37% raw validity, so 20 attempts are plenty. Hardware and geometry never match the paper; the knob stays.

Step 3 — a periodic cubic spline through the points

def fit_spline(pts):
    n = len(pts)
    t_knots = np.linspace(0.0, 1.0, n + 1)
    return scipy.interpolate.CubicSpline(
        t_knots, np.vstack([pts, pts[:1]]), bc_type="periodic")

A cubic spline draws a smooth curve through the points with continuous first and second derivatives (continuous tangent and curvature). Two details make it a closed racetrack:

  • np.vstack([pts, pts[:1]]) — the first point is appended again at the end, so the curve returns to where it started.
  • bc_type="periodic" — forces the derivatives to match at the seam too, so there is no kink where the loop closes.

The spline is parameterized by t ∈ [0, 1]. That parameter is not distance along the track — fixing that is Module 2.

Module 2

Arc-length reparameterization

generator.py · build_track_arrays

The single most important piece of math in the generator. Everything downstream assumes samples are evenly spaced in distance. The spline gives them evenly spaced in an abstract parameter t, which is not the same thing.

The problem, precisely Where the spline curves tightly, equal steps in t cover less ground; on straights they cover more. If you sampled at uniform t, your "2048 evenly spaced points" would bunch up in corners. Curvature, wall spacing, and progress measurement would all be wrong. So we re-index the curve by true distance s.

The four moves

def build_track_arrays(spline, M, oversample):
    P = M * oversample                          # 2048*4 = 8192 fine samples
    t = np.linspace(0.0, 1.0, P, endpoint=False)
    p = spline(t)
    seg = np.linalg.norm(np.roll(p, -1, 0) - p, axis=1)   # |p[i+1]-p[i]|
    cum = np.concatenate([[0.0], np.cumsum(seg)])       # running distance
    L = float(cum[-1])                             # total lap length
    s_uniform = np.linspace(0.0, L, M, endpoint=False)
    t_of_s = np.interp(s_uniform, cum[:-1], t)      # invert s(t) -> t(s)
    C = spline(t_of_s)

(1) Measure. Sample the spline very finely (4× oversampling = 8192 points), and add up the straight-line hops between consecutive samples. This numerically approximates the arc-length integral:

arc length s(t) = ∫0t ‖dpdτ‖ dτ  ≈  Σ ‖pk+1 − pk‖

(2) Invert. We now know distance as a function of parameter, s(t). We want the reverse: given target distances s_uniform = 0, L/M, 2L/M, …, what parameter t reaches each? np.interp does this inversion by linear interpolation. (3) Resample the spline at those t values → the centerline C, now uniform in distance.

Why oversample = 4 (and never below 2)? The chord sum underestimates true arc length on curves. 4× keeps that inversion error well under 1 cm. Cheap insurance; the plan calls it non-negotiable.

Tangents, normals, curvature

    dC = spline(t_of_s, 1)  # d/dt (NOT d/ds) — direction only, magnitude is garbage
    T = dC / np.linalg.norm(dC, axis=1, keepdims=True)
    Nrm = np.stack([-T[:, 1], T[:, 0]], axis=1)      # left normal
    ds = L / M
    dT = (np.roll(T, -1, 0) - np.roll(T, 1, 0)) / (2*ds)   # central difference
    kappa = dT[:, 0]*Nrm[:, 0] + dT[:, 1]*Nrm[:, 1]   # signed

Tangent T — direction of travel. We take the spline's t-derivative purely for its direction, then normalize to unit length (its magnitude is in the wrong units — parameter, not distance — so it's discarded).

Left normal Nrm — rotate the tangent 90° counter-clockwise. Rotating (x, y) by +90° gives (−y, x):

left normal N = ( −Ty,  Tx )

This "left" direction is the ruler for the whole env: width is measured along it, walls sit at ±w·N, and lateral offset is a dot product with it.

Curvature κ — how fast the tangent turns per unit distance. By the Frenet relation, the derivative of the unit tangent with respect to arc length points along the normal, scaled by curvature:

Frenet dTds = κ N  ⟹  κ = dTds · N

The code computes dT/ds with a central difference on the uniform-s samples — (next − prev) / (2·ds) — then dots with N. Dotting with the left normal gives a signed curvature: positive = turning left, negative = right. That sign matters later for steering direction and observations.

The footgun the code deliberately avoids Curvature must come from central differences on the uniform-s samples — never from the spline's t-derivatives. Going through t means chain-ruling d/ds = (d/dt)/(ds/dt), and that ratio is a classic bug magnet. The comment # d/dt, not d/ds is guarding exactly this.

Module 3

Track width

generator.py · draw_width_randoms · width_from_draws

The corridor should breathe — wide straights, tighter corners — but smoothly and seamlessly around the loop. The trick: build the width as a sum of a few sine waves. Sines are periodic by construction, so the seam takes care of itself.

def width_from_draws(draws, cfg):
    _, phase, amp = draws
    u = np.linspace(0, 2*np.pi, cfg.M, endpoint=False)
    w = cfg.w_base + sum(
        a * np.sin((i+1)*u + p) for i, (a, p) in enumerate(zip(amp, phase)))
    return np.clip(w, cfg.w_min, cfg.w_max)

This is a small truncated Fourier series around the loop:

harmonic width w(u) = wbase + Σi=1k ai sin( i·u + φi ),    u ∈ [0, 2π)

Each term is a full number of cycles around the ring (i·u), so w(0) = w(2π) automatically — no discontinuity at the start/finish line. k is a random 2–5 harmonics.

The 1/f amplitude falloff Amplitudes are drawn then divided by their harmonic index: amp = uniform(0.03, 0.12, k) / arange(1, k+1). Higher harmonics (wigglier) get smaller amplitude. This "pink-noise" shaping keeps width variation gentle and organic rather than jagged — the same idea used to make natural-looking terrain and textures.

The final np.clip(w, w_min, w_max) is a hard guarantee: whatever the sines do, the half-width never drops below the phase's floor (0.35–0.60 m) nor above 0.80 m. Given the car is ≈0.14 m half-width, even the tightest corridor leaves real room.

Determinism detail worth its own mention draw_width_randoms is called once per attempt, before the repair loop. If width randoms were redrawn on every repair round, the number of RNG draws would depend on how many repairs happened — and identical seeds could diverge. Drawing once, reusing across repairs, keeps the RNG consumption order fixed. This is what test T3 (bit-identical output) leans on.

Module 4

Validation & repair

generator.py · check · repair · sample_valid_track

A random loop can be undrivable: a corner too tight for the car, a boundary that self-intersects, two sections crossing. Rather than trying to generate perfectly, the design generates loosely, then checks and nudges — a repair-then-reject loop.

The four validity predicates

IDChecksWhy
V1max(|κ|) ≤ kappa_max Corner not tighter than the car can turn. Phase-dependent: 0.4→1.0 m⁻¹.
V2max(w·|κ|) ≤ 0.8 Inner boundary must not fold onto itself. Dimensionless; hard limit 1.0.
V3far-apart-along-arc samples not close in space No near-crossings / pinch points where two track sections nearly touch.
V4L ∈ [25, 90] m Not trivially small, not enormous.

V2 explained. A track boundary is the centerline offset inward by w. On a left turn, the inner (right) boundary is at radius R − w where R = 1/κ. If w ≥ R, i.e. w·κ ≥ 1, the inner edge passes through the center of the turn and folds over itself. Keeping w·|κ| ≤ 0.8 stays safely clear.

V3 — the clever bit: a KD-tree neighbor query

    clearance = 2*w.max() + cfg.clearance_margin
    pairs = cKDTree(C).query_pairs(r=clearance, output_type="ndarray")
    if len(pairs) > 0:
        arc = np.abs(wrap(s[pairs[:, 1]] - s[pairs[:, 0]], L))
        prox = pairs[arc > cfg.arc_sep_threshold]   # far along arc, near in space

A brute-force "is any pair of the 2048 points too close?" is 2048² ≈ 4M comparisons. A KD-tree answers "all pairs within radius r" in roughly O(n log n). query_pairs returns every spatially-close pair; we then keep only pairs that are far apart along the arc. Points that are close both in space and in arc length are just ordinary neighbors on a straight — not a problem. Points close in space but far along the arc mean two different parts of the track are nearly touching — a real defect.

The arc distance uses the wrap helper, which folds a difference into the shortest signed distance around the loop:

signed arc difference wrap(a, L) = ((a + L/2) mod L) − L/2  ∈ (−L/2, L/2]

The repair-then-reject loop

def sample_valid_track(seed, cfg):
    rng = np.random.default_rng(seed)
    for _ in range(cfg.max_attempts):          # 20 — fresh random layout each
        pts = make_centerline(rng, cfg)
        width_draws = draw_width_randoms(rng)     # ONCE, before repair
        for _ in range(cfg.max_repair):       # 5 — nudge the same layout
            C, T, Nrm, kappa, s, L = build_track_arrays(fit_spline(pts), cfg.M, cfg.oversample)
            w = width_from_draws(width_draws, cfg)
            violations = check(C, kappa, w, s, L, cfg)
            if not violations:
                return Track(C=C, T=T, Nrm=Nrm, kappa=kappa, w=w, s=s, L=L, seed=seed)
            pts = repair(pts, violations, C, w, cfg)
    raise TrackGenerationError(seed)

Two nested loops with hard bounds: try up to 20 fresh layouts; within each, try up to 5 gentle repairs before giving up on it. Both bounds are fixed so runtime and RNG usage are bounded and deterministic.

The two repair operators (order matters)

  • Curvature (V1/V2) first: for each violating sample, find the nearest control point and apply one local Laplacian step to it — p ← ½p + ¼(p− + p+). Relaxing a control point smooths the corner near it.
  • Proximity (V3) second: for each too-close pair, find the two nearest control points and push them apart along the line joining them by ½(needed − actual), capped at 0.3 m per round.

Curvature is fixed before proximity because pushing points apart can re-tighten a corner; doing smoothing first gives proximity the last word within a round.

Repair uses zero randomness — on purpose Every repair operation is a deterministic function of the current points and the violations. If repair drew from the RNG, two seeds that hit different numbers of repairs would consume different amounts of the random stream and diverge. No RNG in repair ⟹ identical seeds stay bit-identical through arbitrarily many repair rounds. (Test T6: <0.1% failures over 1000 phase-0 seeds, p99 gen time <20 ms.)

Module 5

Walls — turning a corridor into collidable geometry

walls.py · wall_params · build_model

The Track is math. To crash into a wall the car needs actual MuJoCo geometry. Each boundary becomes a continuous rail of overlapping capsules (cylinders with rounded ends).

Placing K capsules along a boundary

def wall_params(track, side, cfg):        # side +1 = left, -1 = right
    idx = np.arange(cfg.K) * (M // cfg.K)   # K=256 evenly spaced samples (M%K==0)
    edge = track.C[idx] + side * track.w[idx, None] * track.Nrm[idx]
    a, b = edge, np.roll(edge, -1, axis=0)   # consecutive boundary points
    mid = 0.5 * (a + b)
    d = b - a
    seg_len = np.linalg.norm(d, axis=1)
    half_len = cfg.overlap * 0.5 * seg_len   # overlap=1.2 -> 20% longer than the gap
    u = d / seg_len[:, None]

The boundary point is just the centerline pushed sideways by the (signed) half-width along the normal:

boundary edge edgei = Ci + σ·wi·Ni,   σ = +1 (left) or −1 (right)

A capsule is stretched between each pair of consecutive edge points, centered at their midpoint. Making each capsule 20% longer than the gap it spans (overlap = 1.2) means neighbors overlap, so the rail has no gaps to squeeze through even around curvature (test T4 verifies coverage: every point along the boundary is within one radius of some capsule).

The quaternion — the one piece of 3-D rotation math

A MuJoCo capsule points along its local z-axis by default. We need it horizontal, aligned with the boundary direction u. That's a 90° (π/2) rotation about the axis perpendicular to both z and u — which, since u is horizontal, is (−uy, ux, 0).

    c = np.cos(np.pi / 4)                      # cos(θ/2) with θ = π/2
    quat = np.stack([np.full(K, c), -c*u[:,1], c*u[:,0], np.zeros(K)], axis=1)

A quaternion for rotation angle θ about unit axis (ax,ay,az) is:

axis-angle → quaternion q = ( cos θ2,  ax sin θ2,  ay sin θ2,  az sin θ2 )

With θ = π/2, both cos(θ/2) and sin(θ/2) equal cos(π/4) = c. Substituting the axis (−uy, ux, 0) gives exactly the four components above: [c, −c·u_y, c·u_x, 0].

Build once, reposition forever (INV-1 in code)

def build_model(cfg, car_xml_path=CAR_XML_PATH):
    spec = mujoco.MjSpec.from_file(car_xml_path)
    for i in range(2 * cfg.K):                # 512 capsules, once
        g = spec.worldbody.add_geom()
        g.type = mujoco.mjtGeom.mjGEOM_CAPSULE
        g.size[:2] = [cfg.radius, 0.1]        # placeholder half-length
        g.pos = [0.0, 0.0, -10.0]           # parked below the floor
        g.condim = 1; g.priority = 1
        g.contype = 2; g.conaffinity = 1
    model = spec.compile()
    model.opt.disableflags |= mujoco.mjtDisableBit.mjDSBL_MIDPHASE  # see gotcha

A fixed pool of 2·K = 512 capsules is compiled once with placeholder poses. Every reset just overwrites geom_pos, geom_quat, geom_size. Topology never changes → INV-1 holds → the MJX port later is a mechanical array swap.

Contact masking, in one breath Walls get contype=2, conaffinity=1; the car uses the default 1/1. A pair collides iff one's contype bit-ANDs the other's conaffinity. Car(1)&wall(1)=1 ✓ collide. Walls and floor are both worldbody geoms, and MuJoCo never collides two geoms of the same body — so walls ignore the floor and each other for free.

Two gotchas the design cannot live without priority=1 is required, not cosmetic: without it the wheels' condim=3 wins the contact pair and walls silently become frictional, breaking the frictionless-wall design.

MIDPHASE disabled: MuJoCo builds a bounding-volume tree over static (worldbody) geoms at compile time, from the parked poses. Move the capsules afterward and that tree is stale — wall contacts silently vanish once the model is big enough to trigger midphase (verified: 9 cm of penetration, zero contacts). Disabling it forces the dynamic broadphase, which re-reads positions each step. geom_rbound is also refreshed at reset for the same reason.

Module 6

Reset — placing a track, a car, and some noise

env.py · reset · _apply_dr

Reset is where a fresh episode is born. Its RNG draw order is frozen forever — track seed → domain randomization → spawn — so the whole rollout is reproducible.

def reset(self, seed):
    rng = np.random.default_rng(seed)
    track_seed = int(rng.integers(2**63))          # 1) which track
    track = sample_valid_track(track_seed, cfg.gen)
    self._write_walls(track)                     # rewrite the 512 capsules
    self._apply_dr(rng)                          # 2) physics noise
    s0 = rng.uniform(0.0, track.L)              # 3) where on the loop to start
    i = int(s0 / track.L * M) % M
    lateral = rng.uniform(-cfg.spawn_lateral_frac, cfg.spawn_lateral_frac) * track.w[i]
    yaw = np.arctan2(track.T[i, 1], track.T[i, 0])
    self.data.qpos[:] = self.model.qpos0
    self.data.qpos[0:2] = track.C[i] + lateral * track.Nrm[i]
    self.data.qpos[3:7] = quat_from_yaw(yaw)
    mujoco.mj_forward(self.model, self.data)

Spawn placement. Pick a random arc position, place the car on the centerline nudged sideways by a random fraction (±0.25) of the local width, and aim it along the tangent. The height and joint rest come from the compiled model's qpos0 — the settled ride height — so at t=0 only the four wheels touch the floor (test T2). The yaw is packed into a quaternion for a pure z-rotation:

yaw → quaternion q = ( cos ψ2, 0, 0, sin ψ2 )

Domain randomization

def _apply_dr(self, rng):
    f_floor = rng.uniform(*cfg.dr_floor_fric)    # U(0.8, 1.2)
    f_mass  = rng.uniform(*cfg.dr_mass)          # U(0.9, 1.1)
    ...
    m.geom_friction[floor] = base["floor_fric"] * f_floor
    m.body_mass[car]       = base["car_mass"]  * f_mass
    m.body_inertia[car]    = base["car_inertia"] * f_mass   # same factor!

Every episode perturbs floor friction, car mass+inertia, wheel friction, and motor gain by small random multipliers. This forces the eventual RL policy to be robust rather than overfit to one exact physics. Two rules keep it honest:

  • Multiplicative on cached pristine base values (grabbed once at startup), never on last episode's already-randomized values — otherwise the noise compounds and drifts over time.
  • Mass and inertia scale by the same factor — they are physically linked; scaling one without the other would invent an impossible car.
Module 7

Projection — where am I on the track?

projection.py · project

Given the car's (x, y), which point on the centerline is it "at", and how far along? This answers progress (reward) and lateral offset (observation + termination). The subtlety: do it locally, never globally.

def project(track, state, xy, cfg):
    i0 = int(state.s / track.L * M)
    idxs = (i0 + np.arange(-cfg.window_back, cfg.window_fwd)) % M   # 10 back, 40 fwd
    dists = np.linalg.norm(track.C[idxs] - xy, axis=1)
    k = int(np.argmin(dists)); j = int(idxs[k])
    if dists[k] > cfg.gate_scale * track.w[j] + cfg.gate_margin:   # VALIDITY GATE
        return ProjResult(valid=False, ds=0.0, lateral=np.inf, j=j)
    ds = float(wrap(track.s[j] - state.s, track.L))
    lateral = float(np.dot(xy - track.C[j], track.Nrm[j]))
    state.s = float(track.s[j])                        # commit ONLY if valid
    return ProjResult(valid=True, ds=ds, lateral=lateral, j=j)
Why not just find the globally nearest centerline point? On an S-bend or near-crossing, two different parts of the track pass close together. The globally nearest point could snap to the wrong section, teleporting your "progress." So after spawn, the search is restricted to a small window around the last committed position — 10 samples back, 40 forward — and biased forward. The car can only be found near where it just was.

Two quantities come out, both using the Frenet frame from Module 2:

progress & lateral ds = wrap(sj − sprev, L),     lateral = (xy − Cj) · Nj

ds is signed arc progress since the last step (driving backwards gives it negative naturally — no special case). lateral is how far off-center, signed by side, because we dot with the left normal.

Three iron rules (1) Gate before computing ds — an invalid projection contributes zero reward, even on a terminal step. (2) Commit state.s only on a valid projection. (3) If the car outruns the 40-sample forward window (only possible at physics-glitch speeds), the projection goes invalid and the episode ends via E2 — which is exactly the right outcome.

Module 8

Reward & termination

env.py · _reward_and_flags · _check_termination

The reward tells the agent what "good" means. Here it is, in one line:

per control step r = ds − cwall·𝟙[wall contact] − cact·‖at − at−1‖² + Rlap·𝟙[lap done]
  • +ds — go forward. Distance covered this step is the core signal.
  • − cwall (0.05) — a per-step penalty whenever any car geom touched any wall capsule this frame. Presence, not count.
  • − cact (0.01) — squared action change: discourages jerky steering/throttle, encourages smooth control.
  • + Rlap (5.0) — a bonus, paid once, on the step that completes a full lap.
Why the wall penalty is mandatory, not optional The walls are frictionless by design (so they don't act as a free guide-rail). But frictionless walls make sliding along them physically cheap — an agent would happily wall-ride every corner. The per-step contact penalty is the counterweight. Frictionless walls and the contact penalty ship together or not at all; test T7 calibrates cwall so a wall-riding return is ≤ half a clean-driving return.

Six ways an episode ends

MuJoCo/PPO care about the difference between terminated (a real failure — bootstrap value = 0) and truncated (episode cut off, but the world would have continued — keep bootstrapping).

IDConditionFlagMeaning
E1|lateral| > w[j] + 0.1terminatedEscaped the corridor despite walls — a physics anomaly.
E2projection invalidterminatedLost the track (usually a glitch). Neutral, not punitive.
E3chassis z ∉ [0.02, 0.5]terminatedFlipped, launched, or buried.
E4<0.2 m progress over trailing 5 sterminatedStalled. Uses a 250-slot ring buffer of ds.
E5total progress ≥ LtruncatedLap done — success, pays Rlap.
E6t ≥ 60 struncatedRan out of time.

Every terminated case zeroes that step's reward — you don't get paid for the frame you crashed. The stall detector (E4) is a fixed-size ring buffer: each step writes its ds into ds_ring[ptr % 250]; once the buffer is full, if the sum of the last 250 ds values is below 0.2 m, the car is stuck.

Module 9

Observations — the 23 numbers the agent sees

env.py · _obs

The policy never sees the world map or its absolute position. It sees a Frenet-frame snapshot: everything relative to the track under it, plus a preview of what's coming. That is deliberate — global position would let it memorize specific tracks.

Two ideas worth the math

Heading error as sin/cos. The angle between the car's yaw and the track tangent could wrap at ±π and confuse the network. Splitting it into (sin, cos) makes it continuous and unambiguous:

heading error ψerr = ψcar − atan2(Tj,y, Tj,x)  →  (sin ψerr, cos ψerr)

World velocity into the car's own frame. The agent should reason in "forward / sideways", not "east / north". Rotate the world velocity by −yaw:

body-frame velocity vbx = cos ψ · vx + sin ψ · vy,    vby = −sin ψ · vx + cos ψ · vy

The curvature preview — the policy's entire map

    for delta in cfg.obs_preview_deltas:      # {0.25, 0.5, 1.0, 2.0, 4.0} m
        dsamp = max(1, round(delta * M / L))   # meters -> sample count
        jp = (j + dsamp) % M
        obs[k]   = np.clip(track.kappa[jp], -clip, clip)   # upcoming curvature
        obs[k+1] = np.clip(track.w[jp] / cfg.obs_w_norm, -clip, clip)

At five distances ahead (0.25 m to 4 m), the agent gets the upcoming curvature and width. That is all it knows about the road shape — no raycasts, no absolute s, no world position. A distance in meters is converted to a sample offset by Δ·M/L (samples per meter is M/L). This forward-looking, position-free view is what forces the policy to drive rather than memorize.

Module 10

The scripted driver (classical baseline)

drive.py · scripted_action

Before any learning, a hand-written controller proves the tracks are actually drivable. If this classical driver can't lap a track, the generator is broken — you fix the generator, never the test. It has two parts: steering (pure pursuit) and speed (a PD controller).

Pure pursuit — steering toward a point ahead

    i_look = int((s + cfg.lookahead) / L * M) % M    # a point 0.6 m ahead
    target = track.C[i_look] + bias * track.w[i_look] * track.Nrm[i_look]
    rel = target - pos
    y_local = -sn * rel[0] + c * rel[1]           # target's sideways offset in car frame
    Ld = np.linalg.norm(rel)
    curvature = 2.0 * y_local / max(Ld*Ld, 1e-6)
    steer = float(np.clip(curvature * cfg.wheelbase, -1.0, 1.0))

Pure pursuit picks a target a fixed distance ahead on the centerline and computes the curvature of the circular arc that connects the car to it. The classic formula, where Ld is the look-ahead distance and y is the target's lateral offset in the car frame:

pure-pursuit curvature κ = 2yLd²

Curvature times wheelbase gives the steering command (small-angle bicycle model), clipped to [−1, 1] which the env maps to ±0.4 rad. The optional bias shifts the target toward a wall — that's the wall-ride variant test T7 uses to calibrate the penalty.

Speed — slow for corners, PD to hit the target

    kappa_ahead = np.max(np.abs(track.kappa[idxs]))       # tightest corner in next 1.5 m
    v_target = np.sqrt(cfg.a_lat_max / max(kappa_ahead, cfg.kappa_floor))
    v_target = float(np.clip(v_target, cfg.v_min, cfg.v_max))
    throttle = float(np.tanh(cfg.kp_speed * (v_target - v_fwd)))

The target speed comes from a lateral-acceleration budget. Cornering at speed v on curvature κ needs lateral acceleration a = v²κ. Cap it at a comfortable amax = 4 m/s² and solve for the fastest safe speed:

corner speed limit a = v²κ  ⟹  vtarget = √( amax / κahead )

Tight corner ahead → smaller target speed; straight → capped at v_max. Then a proportional controller on the speed error, squashed through tanh to stay in [−1, 1], sets the throttle. Simple, classical, and enough to lap every valid track (test T1: 30/30 laps at the hardest phase).
